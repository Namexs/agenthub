## 0. Counting note (read before quoting a number)

Phase 8 §2's headline says **14 findings closed (1 High, 9 Medium,
4 Low)** plus PH7-L01 accepted with evidence plus PH7-I09 closed as a
bonus. The §2 table itself enumerates **17 closed rows**. The two
counts reconcile exactly if the headline excludes the three rows that
are not full code closures: PH7-M03 (code part closed, procedural part
still open) and PH7-L15/L16 (documentation-only fixes). This file
follows the §2 table row-by-row and marks PH7-M03 as PARTIAL, so the
auditor sees the full picture; the headline "14" is the report's own
conservative count of full closures.

**Status key:** `CLOSED` = fixed in code with test/artifact evidence
(Phase 8 §2) · `PARTIAL` = code part closed, procedural part open ·
`ACCEPTED` = risk accepted with documented evidence, no code fix ·
`DESIGN` = explicit design decision, tested and documented ·
`OPEN` = not fixed in Phase 8 (see `KNOWN_LIMITATIONS.md`) ·
`INFO` = informational, no action required · `CLOSED-P7` = closed
within the Phase 7 review itself · `—` = no Phase 8 disposition
recorded.

**Tally (59):** 17 CLOSED + 1 PARTIAL (M03) + 1 ACCEPTED (L01) +
2 DESIGN (L08, I07) + 1 CLOSED-P7 (L27) + 22 OPEN (21 Low + L25
undispositioned) + 15 INFO (noted, no action required).

**No High or Medium finding is fully open.** The only Medium item with
an open part is the procedural half of PH7-M03.

Phase 9 also formally closed **PH7-L08 / PH7-I07 as a design decision**
(Workstream 1, `agenthub-phase9-readiness/workstreams/01-reward-policy-review.md`):
the threshold policy applies to Attested quests only, because the threshold
is a control over the third party that attests (verifiers) and only the
Attested path has such a party — enforcing a threshold floor on CheckIn /
OnChain would change a metadata byte that is never read at completion and
create false confidence. The table above already records both as DESIGN.
